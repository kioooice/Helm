# Helm · 舵

Helm 探索如何从用户允许使用的记录中，找出有依据、值得关注的变化与反复出现的问题，帮助用户理解自己的处境并作出判断。

当前定位是**个人洞察工具的验证项目**。已有桌面采集与报告原型；发现是否准确、有用、负担足够低，尚未经过真实使用验证。截图、日报、一屏展示、教练角色和未来穿戴设备，都是可选择的方案，不是已经证明的产品答案。

## 要验证什么

用户不想管理越来越多的资料，但可能需要少量值得看的发现：某个问题为什么反复出现、目标是否已经改变、哪些记录之间存在自己未注意到的联系。

默认输出简短，允许查看依据、追问和纠正；不强制恰好三条，也不强迫每天产生变化或行动建议。没有值得报告的发现、暂时不改变、探索与休息，都可以是正常结果。

观察到的行为、对行为的解释、用户确认的目标必须区分。窗口切换不能直接等同于分心，阅读不能直接等同于没有产出。Helm 不应替用户定义成功，也不能从零散记录断言心理状态或因果关系。

## 目前实际能做什么

基于实现提交 `d300e631c9d7e78157fb847b8917116c3bc712ae` 的源码阅读：

- Electron + React + TypeScript 桌面骨架，SQLite 本地存储。
- 屏幕采集、本地 OCR、文本指纹去重、采集控制与隐私暂停。
- 手动生成报告：读取当日保留的 OCR 片段，调用配置的模型服务，保存并显示报告。
- 已有 events、goals、baselines 等存储基础，但结构化事件生成、历史对比、目标反馈尚未接入报告闭环。

**当前不是完整的行为分析或自动日报产品。** 没有验证完整一天的覆盖，也没有实现可靠的证据追溯、用户纠正与后续重新分析。详细状态和已知差距见 [当前实现说明](docs/current-state.md)。

## 当前数据流与边界

截图与 OCR 结果先保存在本机。OCR 方式有两种，由用户在设置里选择：

- **本地 OCR（默认）**：Windows Runtime 识别，截图不出本机。
- **Paddle 云端 OCR（默认关闭）**：启用后，**每张屏幕截图会上传到 `paddleocr.aistudio-app.com`** 做文字识别（用户自己的服务账号）。启用即视为对该外发行为的明确同意；界面上有相应声明。

点击生成报告时，**OCR 文本片段会发送到用户配置的模型服务地址**（发送前有确认步骤）。现有代码没有保证这些文本已脱敏。不能将当前实现描述成"原始 OCR 从不外发"或"仅发送匿名事件"。

默认原始采集保留参数为 12 小时，但清理由启动及特定采集流程触发，并非严格到点删除或安全擦除保证。截图、OCR、派生事件及报告都可能包含敏感信息；结构化不等于匿名化。

当前数据位于 Electron 的 userData 目录，包括 `helm.db`、`helm-ai-config.json`、`helm-ocr-config.json` 和 `auto-captures/`。具体平台路径以运行环境为准。不要将真实记录、配置密钥或本地数据库提交到仓库。

## 近期路线

1. 用少量已有、获准使用的记录验证“有依据的发现”是否值得看，可先人工辅助完成。
2. 修正原型的输入覆盖、外发说明和无依据比较，再接入最小证据与纠正闭环。
3. 在真实试用中判断是否值得自动化，随后再决定输入源、报告节奏与目标支持。

不以代码量、采集时长或报告打开率单独判定产品成功。也不因一次低质量样本失败，就断言整个方向无价值。阶段任务与推进条件见 [PLAN.md](PLAN.md)。

## 分工与开发入口

规划与阶段验收由规划助手负责；具体实现交给执行模型（如 Luna-max）。用户负责目标取舍与个人价值判断，不需要逐文件监督实现。

执行模型先读 [AGENTS.md](AGENTS.md)、[PLAN.md](PLAN.md) 和 [验收约定](docs/acceptance.md)，只执行当前分配的任务包。后续路线不是自动开工授权。

```bash
cd desktop
npm ci
npm run dev
```

构建后预览：`npm run build`，再运行 `npm start`。测试使用 `npm test`，通过 Electron 的 Node 运行以匹配原生依赖 ABI。命令存在不代表已在你的系统验证通过，平台运行与 OCR 支持仍需实测。

部分模块源自 [brain](https://github.com/kioooice/brain)。本次改版仅调整说明与规划，不代表已修复现有代码。
