# Helm · 舵

> 一个私有的注意力记录，和一个帮你掌舵的教练。

Helm 是一个本地优先的桌面应用。它持续观察你的屏幕活动，把它们蒸馏成结构化的事件，
然后在每天（或你设定的时间）给你一份**只有一屏的报告**——告诉你现在的状态，
对照你在乎的目标，帮你一点一点地改变。

它不是又一个"记录你看了什么"的工具。它存在的唯一目的，是让你**看见自己的轨迹**，
然后温和地提醒你：方向偏了，或者，走得不错。

## 为什么做这个

现在的工具分成两派，都不解决真正的问题：

- **稍后读 / 收藏类**（Cubox、Pocket）：你囤了几千条，一条都没再看。
- **记忆 / 时间统计类**（Rewind、RescueTime）：它们给你一堆图表和数据，
  把"解读"的负担留给你。数据没有结论，看两次就不想打开了。

真正的痛点是：**东西又多又杂，你根本不想打开。**

Helm 的答案是——**感知的通道只有一份报告**。
底层可以无限复杂（截屏、OCR、事件抽取、目标对照），但出口永远是一屏：
结论先行，最多三条，只讲变化。不评判，不施压，像一个冷静的教练。

## 它不是什么

- ❌ 不是监控软件。没有老板视角，没有远程查看，数据永远在你自己的机器上。
- ❌ 不是记忆仓库。不提供"搜索我过去看过的一切"。原始截屏 12 小时后自动焚毁。
- ❌ 不是待办清单。它不催你做事，只帮你看清你在把时间花在哪儿。

## 核心理念

| 原则 | 含义 |
|------|------|
| **感知通道只有报告** | 底层随便复杂，出口只有一屏。原始数据不提供"库"可逛，避免积压焦虑。 |
| **蒸馏即焚** | 截屏 → OCR → 结构化事件入库 → 原始图 12 小时后自动删除。离开设备的只有脱敏后的结构化数据，不是你的人生录像。 |
| **感知无关** | 事件表从第一天起就带 `source` 字段（`screen` / `audio` / `manual` / 未来的 `glasses`）。报告引擎只消费结构化事件，不关心数据来自哪里。 |
| **对照，不是陈述** | "今天 Chrome 3 小时"是废话。"比你关注的目标多了 1 小时"才有信息量。每一行都相对基线或目标说话。 |
| **非评判** | 报告的语气是冷静的教练，不是考勤机。负反馈赶客。 |

## 架构

```
┌─────────────────────────────────────────────────────────┐
│  感知层（可替换的数据源）                                  │
│   screen-capture ──┐                                     │
│   (未来: audio, manual, glasses)                         │
└────────┬────────────────────────────────────────────────┘
         │ 原始截图 + OCR 文本（短暂存在）
         ▼
┌─────────────────────────────────────────────────────────┐
│  蒸馏层                                                  │
│   去重 → 会话切分 → AI 结构化事件抽取                      │
│   { app, activity, topic, mode, artifacts, confidence }  │
└────────┬────────────────────────────────────────────────┘
         │ 结构化事件（永久保存）
         ▼
┌─────────────────────────────────────────────────────────┐
│  存储层（SQLite）                                        │
│   events        结构化行为事件（核心资产，带 source）      │
│   reports       每日/每周报告                            │
│   goals         用户确认的目标                           │
│   baselines     纵向趋势与基线（真正的护城河）            │
│   原始截图      12 小时后自动焚毁                         │
└────────┬────────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────────┐
│  报告引擎（唯一界面）                                     │
│   度量（活动分布/注意力主题/专注质量/目标对齐度）           │
│   → 一屏报告：3 个数字 + 1 个发现 + 1 句建议               │
└─────────────────────────────────────────────────────────┘
```

## 技术栈

- **桌面**：Electron + React + TypeScript
- **存储**：SQLite（`better-sqlite3`），数据在 Electron `userData` 目录
- **OCR**：Windows Runtime OCR（本地，不联网），Tesseract 兜底
- **AI**：DeepSeek API（可配置，错误信息自动脱敏 API Key）

## 数据与隐私

数据全部存本地：

- `helm.db`：事件、报告、目标、基线
- `helm-ai-config.json`：本机 AI 配置
- `auto-captures/`：原始截图，**12 小时后自动删除**

原始截图和 OCR 文本**不会**发给任何服务器。只有当你开启 AI 报告功能时，
**蒸馏后的结构化事件**（不含原文）才会发送给你自己配置的 AI 服务商。
